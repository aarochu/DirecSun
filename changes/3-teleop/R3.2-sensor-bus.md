# R3.2: Sensors on one I2C bus

**Status:** planned
**Files:** `firmware/components/direcsun_drivers/{include/direcsun/drivers/{i2c_bus,imu,mag,baro}.hpp,src/{i2c_bus,imu,mag,baro}.cpp}`, `firmware/components/qmc5883p/{qmc5883p.c,include/qmc5883p.h,LOCAL_PATCHES.md}`, `firmware/test_apps/sensors/` (its own IDF project)

## Spec

**Problem:** The three sensor libraries were each validated alone (CONTEXT.md). Together they collide on two points. i2cdev owns I2C port 0, but the QMC driver wants its own bus handle. And the libraries run at different clocks: 1 MHz for esp-idf-lib, a hard-coded 100 kHz for the QMC driver. A third problem is timing: the library's `mpu6050_get_motion` makes two transactions, while FD §9 budgets one 14-byte burst per 2 ms tick.

**Approach:**
- **`i2c_bus`.**
  - Call `i2cdev_init()` once.
  - Create the IMU descriptor with `mpu6050_init_desc(port 0, SDA GPIO5, SCL GPIO6)` and set `dev.i2c_dev.cfg.master.clk_speed = 400000` before the first transaction. The first transaction then creates the bus.
  - Fetch the bus handle with `i2cdev_get_shared_handle(I2C_NUM_0, ...)` and give it to the QMC driver.
  - Internal pull-ups stay off; the Adafruit boards carry 10 kΩ each.
- **`imu`** (FD §10.1).
  - Configure through the library setters: wake with the PLL on the X gyro clock, `SMPLRT_DIV` 0, DLPF_CFG 4, gyro ±2000 deg/s, accel ±4 g.
  - `imu_read(Sample&)` reads all 14 bytes from register 0x3B in one transaction, with `i2c_dev_read_reg(&dev.i2c_dev, 0x3B, buf, 14)`. The configuration stays in the library; only the hot path bypasses it.
  - Each read is timed. Errors and timeouts mark the sample invalid. After 3 consecutive errors the bus is reset once with `i2c_master_bus_reset`.
  - Boot probe: WHO_AM_I must read 0x68, otherwise the fault is IMU_MISSING.
- **`mag`** (FD §10.2). `qmc5883p_init` gets the shared handle, then: continuous mode, 200 Hz output rate, chip ID 0x80. Otherwise the fault is MAG_MISSING, which is not fatal. `mag_poll()` reads the status register and, only when data is ready, the 6 data bytes. The FD §10.2 axis map is a parameter for Set 5; here only the raw axes are exposed.
- **Local patches to the vendored QMC driver**, recorded in `LOCAL_PATCHES.md` with the upstream version and a diff summary:
  1. `qmc5883p_init` takes the SCL speed as an argument. It was hard-coded to 100 kHz.
  2. The sensitivity constants are checked against the QST datasheet (TD §13, the Adafruit-hosted PDF) and corrected if they are wrong. The current 8 G value (12000 LSB/G) is suspected. Heading uses only the ratio of the horizontal axes, so this changes no control behaviour, but `mag_*` telemetry must show real gauss.
- **`baro`**: BMP280 at 0x77 only, the Adafruit default, with `bmp280_init_desc` at 400 kHz. It is optional and read at 1 Hz. It never blocks boot (FD §10.3).
- **`firmware/test_apps/sensors/`**: its own IDF project. It boots the bus, prints the probe results, then reads the IMU at 500 Hz, polls the magnetometer every 2nd tick, and reads the barometer at 1 Hz, printing at 5 Hz. It prints the IMU burst duration: min, median, and max over each second. It also prints error counters.

## Tests
- [ ] Boot probe on the bench rig: WHO_AM_I 0x68, QMC chip ID 0x80, BMP280 chip ID 0x58 at 0x77, all on one bus with no "bus already in use" error.
- [ ] The I2C clock really is 400 kHz, checked two independent ways:
  - The median IMU burst time is about 0.4 ms. It would be about 1.5 ms at 100 kHz and about 0.2 ms at 1 MHz (FD §9.2).
  - The oscilloscope on SCL shows a 2.5 µs period and rise times under 300 ns (TD §5.3). Julian reports the readings.
- [ ] 60 s at 500 Hz IMU reads plus magnetometer polling: 0 errors, 0 bus resets, and IMU max burst under 1 ms.
- [ ] Gyro sign: rotating the rig counter-clockwise by hand (seen from above) gives a positive gyro z, matching the FD §2.3 convention. This records `s_gyro`. If the axis were mapped wrong, z would stay near zero while x or y moved.
- [ ] Magnetometer is alive: rotating the rig through 360° flat makes raw x and y trace a closed loop, not a point (TD T-9's broken-instrument signature). The values are within the chip's range at the sensitivity chosen after the datasheet check.
- [ ] Fault path: with the QMC5883P STEMMA cable unplugged at boot, the log shows MAG_MISSING, and the IMU and barometer still read. With the IMU cable pulled mid-run, the error counter rises, one bus reset happens, and reads recover when the cable is replugged, with no reboot.
