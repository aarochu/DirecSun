## Spec

**Problem:** The box must speak schema v1 (`protocol/schema-v1.json`, FD §15) to the main UI (`frontend/`) and to the bench link module. The backend matches the UI (CONTEXT.md, 2026-10-10). DirecSun1 proved the transport (`esp_http_server` WebSocket on port 81), but only with a test format, a single client, and no controlling-client or heartbeat rules. Parsing must be host-testable against the schema. That means the JSON library has to compile on the desktop too.

**Approach:**
- **JSON library [D].** Vendor cJSON 1.7.19 (MIT), the version already in the lock, into `direcsun_core/third_party/cjson/`. Both the firmware and the host tests compile this one copy, and the `espressif/cjson` registry dependency is dropped. Two copies at different versions would let host tests pass against code the firmware does not run. cJSON is portable C with no IDF includes, so core purity holds.
- **Core `protocol`.**
  - `parse_command(const char*, size_t)` returns a `Command` struct, or a rejection reason string matching FD §15.3: too large over 512 bytes, bad JSON, wrong or missing `v`, unknown `type`, unknown `cmd`, a malformed field, or two `manual` setpoints.
  - `encode_tlm(const Snapshot&, char* buf, size_t)` uses `snprintf` into a fixed buffer, with no heap.
  - `encode_ack`, `encode_event`, and `encode_pong` complete the set. The `ack` echoes the command's `seq` (V-14); every other box message uses the box counter.
- **`wifi`.** A Kconfig menu, "DirecSun network", provides the keys already documented in `sdkconfig.defaults.local.example`: SSID, password, hostname (default `direcsun`), an optional static IP, gateway, and netmask, and a SoftAP mode with its own SSID and password. Behaviour:
  - Station mode with DHCP, power save off, and reconnect on disconnect, as in DirecSun1.
  - mDNS hostname set at start-up.
  - The IP and the `ws://<host>.local/ws` URL are logged on every connect.
  - SoftAP is chosen only at build time. The box never switches modes on its own (FD §15.1).
- **`ws_server`.** `esp_http_server` on port 80, URI `/ws` with `is_websocket` (the UI's default endpoint), at most 3 clients (`max_open_sockets`), and inbound messages capped at 512 bytes.
  - The client table maps socket fd to client id.
  - The controlling client is whoever's `arm` was last accepted (FD §14.4).
  - On disconnect a client is removed. If it was the controlling client, its heartbeat simply expires; there is no instant disarm and no auto re-arm.
- **`comms_task`** (core 0):
  - Validated commands go to the command queue, or `estop` sets the atomic flag. A full queue answers `ack ok:false reason:"busy"`.
  - A `ping` is answered with a `pong` at once and, from the controlling client, updates the heartbeat. Accepted `cmd` and `manual` messages from the controlling client update it too.
  - At 50 Hz it copies the snapshot and broadcasts `tlm` with `httpd_ws_send_frame_async`. A send that cannot be queued is skipped for that client and counted in `tlm_dropped`. Acks and events are never skipped.
- **FD §15.3 gaps that R1.6's schema had to fill** are written into the FD so prose, schema, and firmware agree:
  - the event catalogue: `event:"mode"` and `event:"notice"` (`PARAMS_RESET`);
  - the automatic-transition causes `boot`, `spinup_complete`, and `sun_invalid`;
  - ack `seq` 0 for frames that are too large or not JSON;
  - `psi_ref_deg` null in MANUAL;
  - "too fast" measured on arrival.

  The firmware follows the schema, which is the tie-breaker until the FD says the same.
- **Additive schema changes from R3.6**, which stay v1 under the 2026-10-10 rule in CONTEXT.md:
  - the `HALL_BYPASS` tlm flag and its `notice` event (on and off);
  - the parameter keys `spinup_throttle`, `hall_expect_throttle`, `hall_installed`, and `bench_mode`, with their FD §16 ranges;
  - the refusal reason strings R3.6 fixed.

  Each change gets valid and invalid fixtures, a line in `protocol/README.md` for Aaron's UI, and support in the mock box.
- **Ping forwarding (from R3.6).** Comms forwards every `ping` as a command, so the supervisor owns the heartbeat, and answers with the `pong` itself. `set_params` payloads stay alive in comms until the supervisor's ack for that `seq` is posted.
- **Wire sign conversion (CONTEXT.md, 2026-10-10).** Internally the firmware is counter-clockwise positive (FD §2.3); on the wire, heading, heading reference, rate, `mag_deg`, `sun_deg`, SLEW `psi_ref_deg`, and MANUAL `rate_dps` are clockwise positive to match the UI. `encode_tlm` negates on the way out and `parse_command` negates on the way in. No other code knows the wire frame exists. A host test pins it: an internal state turning counter-clockwise at +10 deg/s with ψ = +30° encodes as `rate_dps` -10 and `psi_deg` -30. Positive control: a test build that skips the conversion fails it.
- **Matching the main UI's reader (found in R1.8).**
  - `frontend/`'s DeviceLink counts every non-`tlm` frame as "ignored" and shows that count.
  - So `event` and `ack` frames go only to clients that have sent at least one message.
  - A read-only viewer, like the UI today, receives only `tlm`. It still sees the mode in every `tlm` frame.
  - `t_ms` is monotonic within a boot, from `esp_timer`. A reboot closes every socket, so the UI never sees time jump backwards on one connection.
- **`tools/capture-box.py`** (venv `websockets`). It connects to the box, sends pings at 5 Hz, records every frame to JSON lines for a duration, and reports the tlm rate, gaps, and round-trip percentiles. Its capture files go through `tools/check-schema.py`.

## Tests
- [x] HT-9 on the host:
  - Every `cmd` form in the schema parses.
  - Oversize, `v` 2, unknown `type`, unknown `cmd`, and `manual` with two setpoints are each rejected with their FD reason.
  - An `ack` echoes the command `seq`.
  - The host test writes one of each encoded message to JSON lines, and `tools/check-schema.py` validates them with 0 failures.
  - Positive control: one deliberately malformed `tlm` that the test writes is rejected by the schema check.
- [ ] Wi-Fi and mDNS on the bench network: the boot log shows the IP and URL; `ping direcsun.local` resolves from the laptop; both the bench console and the main UI's Device link panel connect at `ws://direcsun.local/ws`.
- [ ] Firmware traffic matches the schema: `tools/capture-box.py` for 60 s, then `tools/check-schema.py` on the capture, gives 0 failures across at least 2900 `tlm` frames plus the acks and pongs. This is the first check of the real firmware against the schema, not the mock.
- [ ] The main UI reads the real box. The `frontend/` ground station's Device link, pointed at `ws://direcsun.local/ws`, switches to device mode with its ignored-frame counter at 0. Turning the rig clockwise by hand turns the UI's dial clockwise and makes its heading readout increase. If the sign conversion were missing, the dial would turn the other way. Screenshots are checked by eye.
- [ ] A read-only client that never sends receives only `tlm` frames over 60 s, while mode events are generated by a second client; the UI's ignored counter stays 0. Positive control: a client that has sent a `ping` receives those events.
- [ ] T-11: 10 min capture, `tlm` at 50 Hz with under 1% loss, round-trip p95 under 100 ms.
- [ ] Controlling client and heartbeat, with two browser tabs (needs R3.6):
  - Tab A arms; tab B's `mode` command is refused with "not controlling client", but tab B's `estop` is accepted.
  - Closing tab A starts the ramp-down within 1.5 s, with HEARTBEAT_LOST in the event stream.
  - Reconnecting does not resume anything.
