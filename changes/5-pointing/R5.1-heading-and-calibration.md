# R5.1: Magnetometer heading, calibration, and absolute HOLD

**Status:** proposed, awaiting Julian's approval (issue 80 P1.5, issue 61). It needs T-9 measurements on the real box, so it is specced in two parts; part A can be built and tested on the host now, part B waits for the measurements.
**Files:** `firmware/components/direcsun_core/{include/direcsun/core/estimator.hpp,src/estimator.cpp,src/params.cpp,include/direcsun/core/params.hpp}`, `firmware/main/control_task.cpp`, `firmware/components/direcsun_core/src/protocol.cpp` (`mag_deg`), `protocol/{schema-v1.json,README.md}`, `docs/firmware-design.md` (§10.2, §11.3, §16), `firmware/test/host/test_heading.cpp`, `tools/mock-box.py`

## Spec

**Problem.** `mag_deg` and `sun_deg` are hard-coded `null` in `encode_tlm` (`protocol.cpp`); `set_params` refuses `mag_axis_map`, `mag_cal`, `sun_cal` and `light_threshold` with `not implemented: <key>` (`params.cpp`, `kDeferredKeys`); the heading is gyro-only and `tlm.flags` carries `HEADING_GYRO` on every frame. HOLD therefore holds a heading relative to the last `zero_heading`, not an absolute bearing (PR-3).

**Part A: mechanics, host-testable now.**
1. **Parameters.** `mag_axis_map` (a signed permutation of the three axes, stored as 3 small integers, default negate Y and Z, keep X per FD §10.2), `mag_cal` (hard-iron offset, 3 floats in raw counts, and a soft-iron 2 x 2 matrix on the horizontal plane, 4 floats; identity and zero by default), and the mag-valid flag derived from "`mag_cal` set". `param_version` becomes 3; the first boot of this build loads defaults and sets the `PARAMS_RESET` flag (R4.6), as R3.9 did. Validation: finite, offsets within the sensor's range, the 2 x 2 matrix with a determinant between 0.25 and 4.
2. **ψ_mag.** Each 20 ms window of magnetometer samples is averaged, mapped through `mag_axis_map`, corrected by `mag_cal`, and `atan2` of the horizontal components gives ψ_mag, with the sign chosen so a counter-clockwise turn increases it (FD §11.3).
3. **Complementary filter** (FD §11.3, TD §6.4): `ψ̂ ← ψ̂ + k · wrap(ψ_mag − ψ̂)` with k = 0.01 every 20 ms, only while `mag_cal` is set and the window has samples. `zero_heading` keeps its meaning (an offset); `HEADING_GYRO` is set only while the magnetometer is not fused.
4. **Reporting.** `mag_deg` is the wrapped ψ_mag (clockwise positive on the wire, same sign conversion as `psi_deg`) while `mag_cal` is set, else `null`. `psi_deg` stays relative to the last `zero_heading` unless the operator has not zeroed, in which case an absolute bearing is the filter's output; HOLD and SLEW keep their relative meaning (I-19) and gain no absolute mode until Julian decides how the UI asks for one (open question 1).
5. **Wire.** The schema's `mag_deg` already allows a number; `set_params` accepts the two keys (the ack returns the applied set). Additive, v1 stays.

**Part B: calibration and acceptance, with Julian.** T-9 (the direction check at three wheel speeds) fixes `mag_axis_map`; a 360° rotation fixes `mag_cal` (a bench tool computes the offsets and matrix and sends them with `set_params`); T-17 shows HOLD keeping an absolute heading against pokes. If T-9 shows a speed-dependent offset, the fallback is FD §11.3's per-speed correction table, which is a new spec.

**Open for Julian:** (1) how an absolute HOLD is requested (a new `mode HOLD` field, or a `zero_heading` variant), since today HOLD and SLEW are relative by the V-48 guard amendment; (2) whether `mag_cal` may be set in SAFE only (this spec says yes, like every parameter).

## Tests

- [ ] Host (`test_heading.cpp`): synthetic magnetometer samples for a rotating box (known bearing, known hard-iron offset and soft-iron matrix) give ψ_mag within 0.5° after calibration and 10° or more before it; the sign is counter-clockwise positive; with the filter on, a 5° gyro bias per minute is bounded to under 2° over 10 minutes; with `mag_cal` unset the heading is the gyro integral exactly and `HEADING_GYRO` stays set.
  - Positive control: mutant `mag_sign_flip` (ψ_mag has the wrong sign) is caught by the direction test; mutant `no_hard_iron` (the offset is not subtracted) by the calibration test.
- [ ] Host (`test_params.cpp`): `mag_axis_map` and `mag_cal` round-trip through `set_params`, validation refuses a singular matrix with `invalid param: mag_cal`, the version bump loads defaults from a stored version 2 and sets `PARAMS_RESET`, and `sun_cal` and `light_threshold` still answer `not implemented: <key>` (R5.4).
- [ ] Schema and fixtures: a `tlm` with a numeric `mag_deg` and no `HEADING_GYRO`, and a `set_params` with `mag_cal`, validate; `check-schema`, `check-protocol`, `check-link` pass.
- [ ] `tools/mock-box.py --selftest`: `mag_deg` follows the heading once a calibration is set.
- [ ] `tools/host-test.sh --selftest`, `tools/check-all.sh`, and `tools/check-all.sh --firmware` pass.
- [ ] Hardware (part B), with Julian: T-9 at three wheel speeds, a 360° calibration, and T-17.
