# R5.4: Sun angle and SUN_POINT

**Status:** built, host-verified; hardware pending (T-10 and a lamp)
**Approval:** as R5.1
**Files:** `firmware/components/direcsun_core/{include/direcsun/core/sun.hpp,src/sun.cpp,src/modes.cpp,params.cpp,protocol.cpp}`, `firmware/main/control_task.cpp`, `firmware/test/host/test_pointing.cpp`, `tools/calibrate.py`, `tools/mock-box.py`

## Spec

**Problem:** The wire has `sun_deg`, `sun_valid`, `sun_cal`, `light_threshold`, the mode `SUN_POINT`, and the cause `sun_invalid`; the firmware answered `not implemented`. The UI disables "Sun point" until `sun_valid` is true.

**Approach (FD §11.4, §13.2):**
- **Angle**: d = (A − B) / (A + B) from the two ADC readings (50 Hz, smoothed with a 0.1 s first-order filter), through the piecewise-linear `sun_cal` table (2 to 8 points, d strictly increasing, angle strictly monotonic). Valid only when A + B > `light_threshold`, a table exists, and d is inside the calibrated range (no extrapolation). Internal frame counter-clockwise positive; the wire flips it, including the table's angles.
- **Mode**: `mode SUN_POINT` from READY, closed wheel loop available, sun valid; refusals `not in READY`, `wheel loop not available`, `sun not valid`. ω_cmd = k_ψ · wrap(sun angle), limited to ±90 deg/s with the 1° hold deadband, into the rate loop. While the sun is briefly invalid the command is 0.
- **Exit**: 0.5 s of continuously invalid sun → READY with cause `sun_invalid`; `mode READY` as usual.
- **Parameters**: `sun_cal`, `light_threshold` (0 to 6600 mV), persisted. Default is uncalibrated, so `sun_valid` is false until T-10 sets them.
