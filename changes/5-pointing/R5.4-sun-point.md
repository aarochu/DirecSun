# R5.4: Sun angle and SUN_POINT

**Status:** proposed, awaiting Julian's approval (issue 80 P1.5, issue 61). Calibration (T-10) needs the lamp and the real sensors, so it is specced in two parts.
**Files:** `firmware/components/direcsun_core/{include/direcsun/core/estimator.hpp,src/estimator.cpp,src/modes.cpp,src/control.cpp,src/params.cpp,include/direcsun/core/params.hpp,src/protocol.cpp}`, `firmware/test/host/{test_sun.cpp,test_status_flags.cpp}`, `protocol/{schema-v1.json,README.md}`, `docs/firmware-design.md` (§11.4, §13.1, §16), `tools/mock-box.py`, `frontend/ground-station/src/hardware/modes.ts` (a later UI PR)

## Spec

**Problem.** `sun_deg` is `null` and `sun_valid` false in every `tlm`; `sun_cal` and `light_threshold` are refused; `mode SUN_POINT` answers `not in READY` or `sun not valid` (R4.6) and never runs. FD §11.4 defines the angle; FD §13.1 defines the mode.

**Part A: mechanics, host-testable now.**
1. **Sun angle** (FD §11.4): `d = (A − B) / (A + B)`, valid only when `A + B` exceeds `light_threshold`; `sun_rad = calibration(d)` from the `sun_cal` table (piecewise linear, `d` strictly increasing, 3 to 8 points; identity by default). `sun_valid` is false below the threshold, outside the calibrated range, or while no `sun_cal` is set. A and B are the 4-sample averaged millivolt readings the control task already takes.
2. **Parameters.** `sun_cal` (the table) and `light_threshold` (mV, default 0, range 0 to 3300). `param_version` becomes 3 together with R5.1 (whichever lands first bumps it once; the other adds its keys). Validation: finite, `d` increasing, angles within ±90°.
3. **Reporting.** `sun_deg` is the angle in the wire frame (clockwise positive, same conversion as `psi_deg`) while `sun_valid`, else `null`; `sun_valid` is the boolean.
4. **SUN_POINT.** From READY with `sun_valid` and the wheel loop: enter SUN_POINT with a `mode` event. The attitude loop of R4.3 runs with the reference set so that `sun_deg` goes to 0 (the sensor pair faces the lamp): ψ_ref ← ψ̂ + sun error each tick, same rate loop, same limits (60 deg/s, 120 deg/s²). Refusals (R4.6): `not in READY`, `sun not valid`, `wheel loop not available`.
5. **Exit.** `mode READY` returns to READY. After 0.5 s with an invalid sun angle SUN_POINT returns to READY with cause `sun_lost` (a new cause string, additive); `disarm`, `estop`, heartbeat loss and interlocks give SAFE as in every mode.
6. **Wire.** `set_params` accepts the two keys; the `mode` cause enum gains `sun_lost`. Additive, v1 stays.

**Part B: T-10, with Julian.** The OP550 calibration (a lamp at known angles gives the table and the threshold), then SUN_POINT tracking a lamp. A lamp at the venue is TD §12.3.

**Open for Julian:** the sign and zero of the sensor pair on the built box (which side is A), and whether SUN_POINT should hold against a moving lamp or only settle on it (this spec: track, with the SLEW limits).

## Tests

- [ ] Host (`test_sun.cpp`): a synthetic lamp sweep gives `sun_deg` within 1° of the true angle through a known table; `sun_valid` is false below `light_threshold`, outside the table's range, and with no `sun_cal`; the angle's sign is clockwise positive.
  - Positive control: mutant `sun_sign_flip` is caught by the sign test.
- [ ] Host (`test_modes.cpp`): `mode SUN_POINT` from READY with a valid sun enters SUN_POINT with a `mode` event; each refusal gives its exact string with nothing changed; 0.5 s without a valid sun returns to READY with cause `sun_lost`, not one tick sooner; `mode READY`, `disarm`, `estop` and a lost heartbeat leave it.
- [ ] Host (plant sim): with a lamp 40° off, SUN_POINT turns the box until `sun_deg` is within 3° in under 4 s and holds it.
  - Positive control: mutant `sun_error_sign` makes the box turn away and is caught.
- [ ] Schema and fixtures: `tlm` with a numeric `sun_deg` and `sun_valid` true, `set_params` with `sun_cal`, and a `mode` event with cause `sun_lost` validate; an invalid fixture (a decreasing table) is refused by the firmware's validation test.
- [ ] `tools/mock-box.py --selftest`: SUN_POINT runs against a simulated lamp.
- [ ] `tools/host-test.sh --selftest`, `tools/check-all.sh`, and `tools/check-all.sh --firmware` pass.
- [ ] Hardware (part B), with Julian: T-10 calibration, then SUN_POINT on a lamp.
