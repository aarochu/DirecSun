# R5.3: Respin (desaturation and alternate start speeds)

**Status:** built, host-verified; hardware pending (with Julian present: the wheel changes speed)
**Approval:** as R5.1
**Files:** `firmware/components/direcsun_core/src/{modes.cpp,control.cpp}`, `firmware/test/host/test_pointing.cpp`, `tools/mock-box.py`

## Spec

**Problem:** TD §3.6 makes the lock pin the desaturation actuator: the operator stops and pins the box, the firmware returns the wheel to a start speed, the pin comes out. The UI already offers "Respin wheel…" (marked firmware pending) and `respin` was refused with `not implemented`.

**Approach (FD §13.4):**
- `respin` is accepted from READY by the controlling client, with the closed wheel loop available and the box still (|ω̂| < 5 deg/s; the firmware cannot sense the pin). The optional `wheel_rpm` must be within [Ω_low + 200, cap − 200] (1000 to 3800 rpm); without it the target is the bias.
- Guard order and reasons: `not in READY`, `wheel loop not available`, `invalid setpoint`, `box not still`. The first failing guard names itself.
- READY → SPINUP with that target, event cause `respin`; the wheel loop's reference ramps up or down to it at 400 rpm/s and the mode returns to READY when the wheel sits within 5 % for 0.5 s (cause `spinup_complete`). A respin from READY carries the loop state over (bumpless).
- Ramping down is new: SPINUP used to step the reference to a lower target.
