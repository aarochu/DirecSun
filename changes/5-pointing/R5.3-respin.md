## Spec

**Desaturation (FD §13.4, TD §3.6).** The lock pin is the desaturation actuator. `respin` takes READY back to SPINUP with a new start speed:
- Guards, in order: `not controlling client`, `not in READY`, `box not still` (|ω̂| under 5 deg/s; the firmware cannot sense the pin, so the UI asks the operator to confirm it), `wheel loop not available`, `invalid setpoint` for `wheel_rpm` outside [Ω_low + 200, Ω_cap - 200]. No `wheel_rpm` means the bias.
- Effect: event `mode` SPINUP with cause `respin`; SPINUP completes as after `arm` (within 5 % for 0.5 s) and posts `spinup_complete`. SPINUP's Ω_ref ramp now runs 400 rpm/s in both directions (FD §13.2), so a respin to a lower speed never steps the wheel reference.

**Status flags (R4.1 open question 2).** `FF_TABLE_MISSING` (Hall installed and `ff_count` 0) and `RATE_GAIN_REDUCED` (`rate_gain_scale` below 1) are set in every mode and appear as warning chips in the UI with no UI change. They make the demo preconditions visible: a box without the table refuses SLEW, and a reduced gain slews slowly.

**PARAMS_RESET reaches a client.** Events go only to clients that have sent a message, and the notice was posted on the boot tick when none had. It is now held until the first tick that carries a command from any client.
