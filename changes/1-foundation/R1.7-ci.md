# R1.7: Continuous integration

**Status:** planned
**Files:** `.github/workflows/ci.yml`, `tools/check-all.sh`, `README.md` (status badge and Checks section)

## Spec

**Problem:** Two people push to aarochu/DirecSun. The merge gates in the feature specs run only on whichever laptop runs them, so a push that breaks the firmware build or the wire contract goes unnoticed until someone flashes.

**Approach:**
- **`tools/check-all.sh`** runs every local check in a fixed order, so CI and humans run the same thing:
  1. core purity, plus its selftest;
  2. host tests, plus their selftest;
  3. schema fixtures;
  4. link tests with schema validation of the capture;
  5. CAD staleness, plus its selftest;
  6. with `--firmware`, the firmware build.
- **`.github/workflows/ci.yml`**, workflow `ci`. It runs on push to `feat/**` and `main`, and on pull requests to `main`. Two jobs:
  - `checks` runs on `ubuntu-24.04` with Node 24 and Python 3.12. It runs `pip install jsonschema websockets` (CadQuery is not needed, because the staleness check is hash-based), then `tools/check-all.sh`.
  - `firmware` runs in the container `espressif/idf:v6.0`, or the matching release tag if `v6.0` does not exist; R1.7 verifies which locally with docker first. It runs `idf.py set-target esp32s3 build` in `firmware/` and uploads `build/direcsun.bin` and the `idf.py size` output as artifacts.
  - Checkout uses `submodules: false`. No job needs the skill submodules, and skipping them avoids fetching third-party repos in CI.
