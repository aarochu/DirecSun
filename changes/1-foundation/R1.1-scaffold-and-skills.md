## Spec

**Problem:** The repo holds only a LICENSE. The project is scattered across `~/projects/pocketadcs` (docs, CAD, CAD skill), `DirecSun1` (the verified WebSocket link), `drone-flight-software` (the ESP-IDF setup), and three sensor example projects. Neither Aaron's agents nor a fresh session can find the contracts, the tools, or the workflow.

**Approach:**
- Three submodules, pinned, on https URLs so that Aaron and CI can clone without SSH access to those repos:
  - `.agents/skills/spec-driven-dev` from `https://github.com/ja-zoe/agent-skill-spec-driven-dev.git` at `f8f68ba`.
  - `.agents/skills/cad-skill` from `https://github.com/flowful-ai/cad-skill.git` at `fe42159`. Its SKILL.md is named `parametric-3d-printing`.
  - `.agents/vendor/awesome-esp-ai` from `https://github.com/pedrominatel/awesome-esp-ai.git` at `ed3956d`, with relative symlinks `.agents/skills/esp-idf -> ../vendor/awesome-esp-ai/skills/esp-idf` and `.agents/skills/esp-idf-components -> ../vendor/awesome-esp-ai/skills/esp-idf-components`. That repo has no license file, so it is referenced as a submodule and never copied into this MIT repo.
- A `.claude -> .agents` symlink, following the ramen-software pattern: `.claude/skills/*` and `.claude/settings.json` resolve for Claude Code, and `.agents/skills` serves other agents.
- `.agents/settings.json` holds the two spec-gate hooks exactly as the skill's `hooks/README.md` specifies: PreToolUse on Bash runs `"$CLAUDE_PROJECT_DIR"/.claude/skills/spec-driven-dev/hooks/spec-gate.sh pre-merge`, and Stop runs `... stop`. They need bash and jq, both present.
- `.gitignore` gets the repo-wide entries: `.claude/settings.local.json`, `.venv/`, `__pycache__/`, `*.pyc`, `.DS_Store`, `.vscode/*` except `extensions.json`. Area-specific entries come with their features: firmware build outputs in R1.4, CAD outputs outside `cad/out` in R1.3.
- `README.md`: what DirecSun is (two paragraphs, linking the TD), the layout table from CONTEXT.md, and a Quickstart section that each later feature extends with its own commands.
- `AGENTS.md`: the agent entry point. It covers: read `changes/CONTEXT.md` first; the spec-driven-dev workflow and branch names; the binding contracts (FD §2, §13, §14, §15, §21 and TD §8.5); and the hardware safety rule. `CLAUDE.md` contains only `@AGENTS.md`, so Claude Code and other agents read one file.
- Known gap, logged rather than patched: the spec-gate Stop hook's drift nudge only inspects `src prisma migrations e2e`, so it never fires for `firmware/`, `ground/`, or `cad/`. Filed upstream as https://github.com/ja-zoe/agent-skill-spec-driven-dev/issues/1. The pre-merge gate is unaffected.
