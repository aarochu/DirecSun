Every later edit then shows as a diff against the original.
2. **Edit commits.** Each edit is logged in the document's own validation log: a new TD §12.4 subsection "Repository import, 2026-10-10", and new FD §23 rows.
   - **Name and paths.** Rename PocketADCS to DirecSun, with the title noting "formerly PocketADCS". Replace `~/projects/pocketadcs/...` and `~/Downloads/...` with repo paths. Rewrite TD §8 for the new layout: `cad/out/`, `tools/build-cad.sh`, `.venv` from `tools/bootstrap-venv.sh`, the cad-skill submodule path. The commit policy moves to the CONTEXT.md git flow.
   - **Platform.** Rewrite TD §6.1 and FD §6, §7.2, §15.2, §18, §19.3, and §22 for ESP-IDF v6.0 and C++17. That means `esp_http_server` WebSocket (verified in DirecSun1), cJSON from `espressif/cjson`, the `gptimer` tick, and the RMT bytes encoder, replacing Arduino `loop()`, arduinoWebSockets, ArduinoJson, and PlatformIO. The FD §18.1 layout becomes `firmware/components/{direcsun_core,direcsun_drivers,direcsun_comms}` plus `firmware/test/host`. Close FD §24 Q1 (toolchain), Q4 (the controlling client is Aaron's UI through `ground/link`), Q5 (the wire stays CCW-positive and the UI converts), and Q6 (additions approved).
   - **Network.** Rewrite TD §7.1 and FD §15.1 for STA with DHCP and mDNS hostname `direcsun` (`ws://direcsun.local:81/`). Static IP and SoftAP become menuconfig options, and credentials live in `sdkconfig.defaults.local`. The OM5P-AC is one possible access point, not a requirement.
   - **Approved additions, written into the TD body** (not only into FD logs): `disarm`; the 0.5 s dwell at bias before READY; the magnetometer and sun guards; `respin` replacing the TD §10.2 automatic dump (V-2); `HALL_SILENT` (V-11); and the controlling-client heartbeat rule (V-15).
   - **Approved corrections, written into the TD body:**
     - V-1: K_ω = 0.0129, and the T-3 pass band is measured against I_b = 1.03e-3.
     - V-4: the magnetometer axis map negates Y and Z.
     - V-5: the motor field can alias at the 93 to 467 Hz electrical frequency.
     - V-7: control uses a fast single-period wheel-speed estimate and the interlocks use the 4-period median.
     - V-9: the gyro runs at ±2000 deg/s.
     - V-14: an `ack` echoes the command's `seq`.
     - Also V-3, V-18, V-19, V-20, and V-21, which are plain fixes.
   - **New MANUAL mode**, approved 2026-10-10, written into the TD §2 modes table, TD §6.6, TD §7.3, FD §13, and FD §15:
     - **Entry.** From READY only, by `{"cmd":"mode","mode":"MANUAL","input":"throttle"|"wheel"|"rate"}`. It is refused, with a reason, if the firmware has not built that input's loop yet. It exits on `mode READY`, `disarm`, `estop`, or any interlock.
     - **Setpoints.** Exactly one of three forms, accepted only from the controlling client, only for the active input, and at up to 20 Hz:
       - `{"cmd":"manual","throttle":n}`, clamped to the parameters `manual_throttle_min..manual_throttle_max`.
       - `{"cmd":"manual","wheel_rpm":n}`, clamped to [Ω_low, Ω_cap].
       - `{"cmd":"manual","rate_dps":n}`, clamped to ±90 deg/s.
     - **Heartbeat and staleness.** Each setpoint counts as a heartbeat. Staleness (approved 2026-10-10): if setpoints stop for 250 ms while pings continue, the `rate` input falls to ω_cmd = 0, and `throttle` and `wheel` hold their last value. The 1 s heartbeat rule still ramps everything down.
     - **Safety.** Every interlock stays active. No input can command past the cap or below the low limit.
   - **Diagrams.** Rebuild the three lost diagrams in Mermaid:
     - TD §2 system architecture, adapted from FD §4.1.
     - TD §6.6 mode state machine, including MANUAL.
     - TD §11 build roadmap: five phases and four gates.
   - **Style.** Replace em dashes with plain punctuation (owner style). This affects 21 in the FD and 0 in the TD.
3. `docs/sizing.py` keeps its `../cad` import path, which still works because `cad/` and `docs/` stay siblings. `docs/README.md` indexes the documents and restates the precedence rule from CONTEXT.md.
