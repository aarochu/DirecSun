# R1.4: Firmware skeleton (ESP-IDF v6.0, C++17, XIAO ESP32-S3)

**Status:** in progress
**Files:** `firmware/CMakeLists.txt`, `firmware/sdkconfig.defaults`, `firmware/sdkconfig.defaults.local.example`, `firmware/dependencies.lock`, `firmware/.gitignore`, `firmware/main/{CMakeLists.txt,idf_component.yml,app_main.cpp}`, `firmware/components/direcsun_core/CMakeLists.txt`, `firmware/components/direcsun_drivers/{CMakeLists.txt,include/,src/}`, `firmware/components/direcsun_comms/{CMakeLists.txt,include/,src/}`, `firmware/components/qmc5883p/` (vendored), `tools/idf.sh`, `.vscode/extensions.json`

## Spec

**Problem:** There is no buildable firmware project. The FD's toolchain (Arduino-ESP32, PlatformIO) was replaced by plain ESP-IDF to match the validated sensor libraries and the drone environment. Those libraries have never been built together, or with C++ application code. Integration failures should surface now, not in the middle of Set 3.

**Approach:**
- **Project.** Project name `direcsun`, with `idf.py` run from `firmware/`. `firmware/CMakeLists.txt` forces C++17 (`idf_build_set_property(CXX_COMPILE_OPTIONS "-std=gnu++17" APPEND)`) and sets `PROJECT_VER` from `git describe --always --dirty`. It sets `SDKCONFIG_DEFAULTS` to `sdkconfig.defaults`, plus `sdkconfig.defaults.local` when that file exists.
- **`sdkconfig.defaults`.** Port the drone's annotated file section by section: target esp32s3, 240 MHz, `-O2` (perf), `FREERTOS_HZ=1000`, the core-affinity pins, both watchdogs on, run-time stats, the I2C ISR in IRAM, and the i2cdev new driver. Add:
  - `CONFIG_HTTPD_WS_SUPPORT=y` and `CONFIG_ESP_WIFI_STA_DISCONNECT_PM_ENABLE=n`, both from the verified DirecSun1.
  - 8 MB flash, which is what the XIAO ESP32-S3 has, with `CONFIG_PARTITION_TABLE_SINGLE_APP_LARGE=y` so Wi-Fi, httpd, and mDNS fit in the app partition. The validated examples ran with the 2 MB default.
  - C++ exceptions and RTTI off. These are IDF defaults, pinned explicitly.
  - Primary console on UART0 with the secondary on USB-Serial-JTAG, which is how the validated examples reached USB.

  Every line carries a one-line reason, like the drone file. The system task watchdog stays at 5 s; the 100 ms control-task watchdog belongs to Set 3.
- **`sdkconfig.defaults.local.example`.** Documents the Wi-Fi keys that Set 3's Kconfig menu will read. In this feature it is only an example file.
- **`main/idf_component.yml`.** Requires `idf: ">=6.0,<6.1"`, `esp-idf-lib/mpu6050: "^2.1.9"` and `esp-idf-lib/bmp280: "^1.0.7"` (the validated versions), plus `espressif/mdns` and `espressif/cjson`, because v6.0 bundles neither. Versions are resolved by the component manager and recorded in `dependencies.lock`, which is committed for reproducible builds on Aaron's machine and in CI.
- **`components/qmc5883p/`.** A verbatim copy of `~/projects/qmc5883p-espidf-example/components/duruofu__qmc5883p`, the validated copy (identical to the drone's apart from YAML quoting), with its license kept. No edits here. The 400 kHz and sensitivity fixes land in Set 3 as documented local patches.
- **Components.** Each gets a CMakeLists and an empty `include/` and `src/`:
  - `direcsun_core`: pure C++17 with no `REQUIRES`. R1.5 fills it.
  - `direcsun_drivers`: `REQUIRES direcsun_core mpu6050 bmp280 qmc5883p`.
  - `direcsun_comms`: `REQUIRES direcsun_core esp_http_server esp_wifi mdns cjson`.

  `main` requires all three, so every managed component is compiled and linked now rather than found broken later.
- **`app_main.cpp`.** `extern "C" void app_main()` logs the project version, IDF version, chip model and revision, flash size, and "DirecSun skeleton". No tasks yet.
- **`tools/idf.sh`.** Sources the EIM activation script for v6.0 (`~/.espressif/tools/activate_idf_v6.0.sh`, overridable with `DIRECSUN_IDF_ACTIVATE`), changes into `firmware/`, and runs `idf.py "$@"`.
- **`firmware/.gitignore`.** `build/`, `sdkconfig`, `sdkconfig.old`, `managed_components/`, `sdkconfig.defaults.local`.
- **`.vscode/extensions.json`.** Recommends `espressif.esp-idf-extension`. Machine-specific settings stay untracked.

## Tests
- [ ] Clean build from a fresh clone: `tools/idf.sh set-target esp32s3 && tools/idf.sh build` exits 0. The log shows target esp32s3 and the resolved versions of mpu6050, bmp280, i2cdev, mdns, and cjson.
- [ ] The libraries really compiled: `firmware/build/compile_commands.json` has entries for `mpu6050.c`, `bmp280.c`, `i2cdev.c`, and `qmc5883p.c`. A green build without them would only prove that an unlinked `main` compiles.
- [ ] C++17 is in effect: the compile commands for `app_main.cpp` contain `-std=gnu++17`, with no later `-std=` flag overriding it.
- [ ] The defaults took effect: the generated `firmware/sdkconfig` contains `CONFIG_IDF_TARGET="esp32s3"`, `CONFIG_FREERTOS_HZ=1000`, `CONFIG_HTTPD_WS_SUPPORT=y`, `CONFIG_ESPTOOLPY_FLASHSIZE_8MB=y`, and `CONFIG_PARTITION_TABLE_SINGLE_APP_LARGE=y`.
- [ ] Hardware, with the rig on USB. Nothing spins here: there is no DShot code, and the ESC may be unpowered. First, `esptool --port <port> flash-id` reports 8 MB, which validates the flash assumption before it is trusted. Then `tools/idf.sh -p <port> flash monitor` boots and prints the banner with the version, `esp32s3`, and `8MB`, with no panic or watchdog reset over 60 s.
