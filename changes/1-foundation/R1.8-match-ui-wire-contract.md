# R1.8: Make the wire contract match the main UI

**Status:** planned
**Files:** `protocol/schema-v1.json`, `protocol/README.md`, `protocol/examples/` (only where a description or fixture states the sign or endpoint), `ground/link/direcsun-link.js`, `ground/link/direcsun-link.test.mjs`, `ground/link/README.md`, `ground/console/index.html`, `tools/mock-box.py`, `README.md` (Ground link and console), `docs/firmware-design.md` (§2.3, §4.2, §15.1 to §15.3, §17, §23, §24), `docs/technical-design.md` (§7.1, §7.2, §12.4)

## Spec

**Problem:** On 2026-10-10 Aaron's `frontend/` (PR #1) became the main UI, and the owner decided the backend matches it. The UI disagrees with the Set 1 contract in two places.
- **Sign.** The UI treats positive heading as clockwise seen from above: "rotate right" is +90°, and its dial turns clockwise. The schema, FD §2.3, §15.3, and §17, the link module, and the console all say the wire is counter-clockwise positive.
- **Endpoint.** The UI defaults to `ws://192.168.4.1/ws`: port 80, path `/ws`. Set 1 documents port 81 at `/`.

The firmware does not speak the wire yet (R3.5), so this is the cheapest moment to fix the contract.

**Approach:**
- **Sign, two layers** (CONTEXT.md, Conventions).
  - FD §2.3 keeps the internal counter-clockwise frame for the physics and control math, and gains a "wire frame" row: `psi_deg`, `psi_ref_deg`, `rate_dps`, `mag_deg`, `sun_deg`, SLEW `psi_ref_deg`, and MANUAL `rate_dps` are clockwise positive on the wire.
  - The firmware's protocol encode and decode is the only place that converts (R3.5 implements it).
  - The schema field descriptions, `protocol/README.md`, the console's "CCW +" labels and footer, the link README, and FD §15.3 and §17 all say clockwise positive.
  - The mock box's values need no change (it is a stub), but its docstring states the wire frame.
  - **Versioning.** This is a v1 correction, not a v2 break: no backend has ever emitted v1, and the only real consumer (the main UI) already assumes clockwise. `protocol/README.md` records it under a "Changes" heading for Aaron.
- **Endpoint.**
  - FD §4.2, §15.1, and §15.2 and TD §7.1 and §7.2 change to port 80, path `/ws`: `ws://direcsun.local/ws` in station mode, and `ws://192.168.4.1/ws` in SoftAP mode, exactly the UI's default.
  - The link module's default URL and the console's default and hint text match.
  - The mock box serves `/ws`. It refuses any other path with an HTTP 404, so a client pointed at the wrong path fails the way it would against the firmware. It keeps listening on 8081 by default, because binding port 80 needs root on Linux.
- **FD §17 rewrite.** "Integration with the ground station" becomes the integration contract with `frontend/`. Facts read from its source on PR #1 head 622150a:
  - `parseTelemetry` accepts `type:"tlm"` with `v` 1 or absent, and requires numeric `psi_deg`.
  - It reads `seq`, `t_ms`, `mode`, `psi_deg`, `psi_ref_deg`, `rate_dps`, `wheel_rpm`, and `vbat`.
  - It never sends.
  - It does not auto-reconnect.
  - Its judge sequence is rotate ±90°, hold 1 s, return, at 60 deg/s and 120 deg/s².
  - It loads `/assets/direcsun.glb` when present.

  The sign row and the V-16 and V-17 findings close. FD §24 Q5 closes too, since the wire now follows the UI.
- **Log.** One FD §23 row and one TD §12.4 row per change.
