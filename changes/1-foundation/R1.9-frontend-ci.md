# R1.9: The main UI in CI and in the repo guides

**Status:** done
**Files:** `.github/workflows/ci.yml`, `tools/check-all.sh`, `README.md` (layout, Quickstart: Frontend), `AGENTS.md` (skills and ownership)

## Spec

**Problem:** `frontend/` is the main UI, but the CI from R1.7 does not build or test it, and the repo guides still describe the UI as external. A change on the backend side, like R1.8's schema descriptions, or on the frontend side, could break the UI with nothing noticing.

**Approach:**
- **CI.** A third job `frontend` in `ci.yml` on `ubuntu-24.04`, with Node 22 (the frontend README's minimum). In `frontend/`: `npm ci`, `npm run typecheck`, `npm test`, then `npm run test:e2e`. The e2e step uses the runner's preinstalled Google Chrome, the `chrome` channel the Playwright config asks for; R1.9 confirms that Chrome is present on the runner image rather than assuming it. Playwright's report and test results are uploaded on failure.
- **`tools/check-all.sh --frontend`** runs the same four commands locally, logging to `build/check-all/frontend-*.txt`. It stays opt-in like `--firmware`, because it needs Node 22 and Chrome.
- **Guides.**
  - The README layout table gains `frontend/`, and the Quickstart gains a Frontend subsection that points at `frontend/README.md`.
  - The "Ground link and console" subsection says these are engineering bench tools.
  - AGENTS.md names `frontend/` as Aaron's main UI and repeats the rule that the backend matches it.
