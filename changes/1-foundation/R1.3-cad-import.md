# R1.3: Import the CAD and build cad/out

**Status:** tests passing
**Files:** `cad/*.py` (18 scripts), `cad/README.md`, `cad/out/*.stl`, `cad/out/*_preview.png`, `cad/out/manifest.json`, `tools/bootstrap-venv.sh`, `tools/requirements.txt`, `tools/build-cad.sh`, `tools/check-cad-stale.py`, `.gitignore`

## Spec

**Problem:** The CAD sources and their outputs live in an uncommitted pocketadcs repo. About 30 MB of STL, STEP, PNG, logs, and run JSON sit next to the scripts, with no record of which script version produced which file. Printing needs a working CadQuery venv, which Aaron may not have while he is fighting the printers.

**Approach:**
- **Sources.** Copy the 18 `.py` scripts and `cad/README.md` from `~/projects/pocketadcs/cad`: `stack.py`, `assembly.py`, and 16 part scripts. Do not copy outputs, `__pycache__`, `.run_*.json`, or logs. Scripts stay unchanged except for paths in docstrings. The README commands change to the `tools/` entry points.
- **Venv.** `tools/requirements.txt` pins the working pocketadcs venv exactly, taken from its `pip freeze` (cadquery 2.8.0, cadquery-ocp 7.9.3.1.1, trimesh 4.12.2, numpy 2.5.3, and the rest). It also adds `jsonschema` and `websockets` for R1.6's tools. `tools/bootstrap-venv.sh` creates `.venv` with `python3.12`, installs the file, and fails loudly if `python3.12` is missing.
- **Build.** `tools/build-cad.sh [part...]` is the only producer of `cad/out/`. For each part script (by default, every script except `stack.py` and `assembly.py`):
  - Run `.agents/skills/cad-skill/run_cadquery_model.py cad/<part>.py --preview --strict`.
  - Fail if the JSON reports `success` or `watertight` false, or reports zero STLs.
  - Move that run's STLs and preview PNGs into `cad/out/`, and its STEP into `cad/out/`, where STEP is gitignored.

  The runner only discovers outputs in the script's own directory, so the scripts keep writing next to themselves and the build moves the files. The vendored cad-skill runner is not modified. After the parts, the build runs `cad/assembly.py` and fails on a nonzero exit, which includes a missed positive control; it then moves `assembly_view.stl` and `assembly.step` the same way. Finally it writes `cad/out/manifest.json`, recording for each output the sha256 of its producing script, the sha256 of `stack.py` at build time, and the output's own sha256.
- **Staleness check.** `tools/check-cad-stale.py` uses only the standard library, needs no CadQuery, and is fast enough for CI. It recomputes the source hashes and fails, naming each output whose script or `stack.py` changed since the manifest. It also fails if a committed STL's hash differs from the manifest, which means someone edited it by hand. `--selftest` copies the tree to a temp directory, appends a comment to `stack.py` there, and asserts that the check fails.
- **`.gitignore`.** Add `cad/*.stl`, `cad/*.step`, `cad/*_preview.png`, `cad/.run_*.json`, `cad/.*.log`, `cad/out/*.step`.

Expected outputs: 16 part scripts produce 17 printable STLs (`battery_holder_cap.py` writes `battery_cap_a` and `battery_cap_b`), plus `assembly_view.stl` from `assembly.py`, for 18 STLs in all.

## Tests
- [x] From a fresh clone with no `.venv`, `tools/bootstrap-venv.sh` succeeds, and `.venv/bin/python -c "import cadquery; print(cadquery.__version__)"` prints `2.8.0`.
- [x] `tools/build-cad.sh` exits 0 and prints one result per part script: 16 results, each with success and watertight true. The script fails if the count is not 16, so an empty loop cannot pass.
- [x] The same run's `cad/assembly.py` output reports all six positive controls detected and no overlaps above 0.5 mm³.
- [x] The import changed no geometry. For each of the 18 STLs that also exists in `~/projects/pocketadcs/cad`, trimesh volume and bounding box match within 1e-6 relative. A mismatch is investigated, because old outputs may simply be stale, and the cause is recorded in Notes rather than waved through.
- [x] `tools/check-cad-stale.py` passes on the fresh build, and `tools/check-cad-stale.py --selftest` passes, meaning it detected the injected change.

    - The assembly preview is rendered without `--strict`, because the viewing model is not watertight by design.
