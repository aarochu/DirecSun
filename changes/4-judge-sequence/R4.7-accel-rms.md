# R4.7: Send accel_rms_g in bench telemetry

**Status:** implemented on a draft branch, awaiting Julian's approval of the spec
**Files:** `firmware/components/direcsun_core/{include/direcsun/core/estimator.hpp,include/direcsun/core/snapshot.hpp,src/estimator.cpp,src/protocol.cpp}`, `firmware/main/control_task.cpp`, `firmware/test/host/{test_accel_rms.cpp,test_protocol.cpp,CMakeLists.txt}`, `tools/{host-test.sh,mock-box.py}`, `docs/firmware-design.md` (§19.2), `protocol/README.md`

## Spec

**Problem.** The schema (`tlm.accel_rms_g`, bench mode only) and FD §19.2 define the field for T-7 (wheel imbalance), but the firmware never sends it: the bench block of `encode_tlm` carries only `gyro_raw`, `mag_raw`, `sun_a_mv` and `sun_b_mv`. The ground station parses the field and has nothing to show (issue 66, issue 80 P1.3).

**Approach.**
- `AccelRms` (core, pure, host-tested): a 100-sample window (200 ms at 500 Hz, exactly twelve turns of a 3600 rpm wheel). Each axis has its window mean removed, so gravity and tilt drop out. `rms_g()` is the square root of the mean total variance over the three axes, in g. It is a broadband figure, not the amplitude at the wheel frequency: the washer procedure of TD §4.6 compares readings at one wheel speed, which this serves. A per-frequency amplitude would need an FFT or a Goertzel at the Hall frequency, which stays with TD §4.6 step 5 (influence-coefficient balancing).
- The control task feeds every valid IMU sample into it and, on the 50 Hz snapshot cadence and only while `bench_mode` is true, copies `rms_g()` into the snapshot. Outside bench mode the field is absent from `tlm`, as the schema says, and nothing is computed.
- `encode_tlm` writes `"accel_rms_g"` with 4 decimals in the bench block.

**Not in this feature.** The balancing tool in the ground station (issue 66; the procedure in TD §4.6 and the TD §7.4 scope are for Julian to agree). Using the field for T-7 needs the wheel spinning, which is Julian's.

## Tests

- [x] Host (`test_accel_rms.cpp`): a still box at any tilt reads under 1e-4 g; 0.05 g at 60 Hz on x reads 0.05 over root two within 2 %; axes add in quadrature; a vibration that stops leaves the window after exactly 100 samples; fewer than two samples read 0.
  - Positive control: mutant `rms_keeps_dc` (the window mean is not removed) is caught by this test in `tools/host-test.sh --selftest`.
- [x] Host (`test_protocol.cpp`): the bench `tlm` carries `"accel_rms_g":0.0312` and validates against the schema (HT-9); the non-bench `tlm` has no such field (the existing SAFE case).
- [x] `tools/mock-box.py --selftest`: `accel_rms_g` is absent outside bench mode, present in it, and larger at speed than at rest.
- [x] `tools/check-all.sh` passes (9 of 9).
- [ ] `tools/check-all.sh --firmware`: the firmware build with the `control_task.cpp` change. Not run here (no ESP-IDF); the change is three lines. CI builds it.

## Notes / log
- 2026-10-11: Built on the R4.1 stack. The window is a ring of 100 x 3 floats (1.2 KB). The mean-removal and the sum run over 300 values once per 20 ms and only in bench mode, so the 500 Hz tick pays only the 3-float store (FD §9.2 has the budget: V-60 measured the worst tick at 1.4 to 1.9 ms of 2 ms).
