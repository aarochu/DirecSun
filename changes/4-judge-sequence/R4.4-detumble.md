## Spec

**Problem:** PR-1 says a judge can spin the box by hand in READY and watch it come to rest. FD §13.2 makes that a named wire mode, DETUMBLE, so the UI and the demo script can say "detumble" and telemetry can be logged against PR-1. The UI already has the button (`frontend/ground-station/src/hardware/modes.ts`); the firmware before PR 86 refused it with `not implemented`. Separately, Set 4 is where the box first runs closed-loop with the wheel at bias, so it is where the TD §9.2 safety tests (T-12 ESC signal loss, T-13 interlocks) get run on the integrated build. Neither needs a new loop: DETUMBLE is the rate loop that READY already runs, at ω_cmd = 0.

**Behaviour (FD §13.1, §13.2, TD §6.6; as first built at a15021d and as on the R4.1 stack):**
- **Entry.** `mode DETUMBLE` is accepted from READY only, from the controlling client, and only when the wheel loop is available: the Hall installed and `ff_count` 8, the full T-5 table (`wheel_loop_available`, `controllers.cpp:39`; `validate_params` accepts only 0 or 8 points), V-43, as for HOLD and SLEW. The ack is `ok`, the event is `mode` with `mode` DETUMBLE and `cause` `mode`, and `tlm.mode` becomes DETUMBLE.
- **Refusals, exact strings, in firmware order:** `not controlling client`; then `not in READY` from every other state, SAFE, SPINUP, MANUAL, HOLD, SLEW and DETUMBLE itself; then `wheel loop not available`. (`not armed` is `mode READY`'s refusal in SAFE only.)
- **Controller.** Identical to READY: wheel loop plus rate loop at ω_cmd = 0, the V-46 stick-slip bleed, `rate_gain_scale` applied as in READY. Nothing in DETUMBLE overrides a gain. `tlm.psi_ref_deg` is null (FD §15.3), heading keeps integrating (R4.2), and MOMENTUM_OK, MOMENTUM_NEAR_LIMIT and MOMENTUM_SATURATED are reported as in READY.
- **Exit.** `mode READY` gives READY with a `mode` event and cause `mode`. `disarm`, `estop`, heartbeat loss and every interlock behave exactly as from READY: the same ramp-down or the same instant cut, the same events. No other path leaves DETUMBLE.
- **Why READY already detumbles.** READY and DETUMBLE are the same controller (FD §13.2), so a box spun by hand while in READY is already damped. A trial therefore starts with the box in DETUMBLE and at rest, and the hand spin happens inside the mode (see T-15 below). The literal TD wording "spin, then enter Detumble" is covered by R3.9's READY hand-spin test, because the two modes cannot differ in behaviour.
- **Absorbable spin.** The wheel can absorb 1.58 rev/s toward the cap and toward the low limit (TD §3). With R3.9's V-52 reference floor (Ω_low + 100) the low-side figure is about 1.48 rev/s [C]. Beyond that the reference clamps, MOMENTUM_SATURATED is set, and the box keeps part of its rate. That is a physical limit, not an error: no interlock may trip because of it.

**Gain precondition.** PR-1 is verified at `rate_gain_scale` 1 (R3.9, V-47); at the post-reset 0.2 it damps a push but does not meet the 5 deg/s in 5 s target. DETUMBLE does not raise the gain on entry (rejected: a per-mode gain would make DETUMBLE differ from READY and contradict FD §13.2). T-15 therefore requires scale 1 to have been sent. R4.6's status flag `RATE_GAIN_REDUCED` tells the operator, in every mode, and the preflight below checks it.

**T-12 and T-13 on the integrated box.** TD §9.2 is the source. These procedures make it runnable; they add no firmware.
- **Rig S** (used for everything except T-13 free-box ramp): box clamped to the bench with the lock pin in, guard ring fitted, bench supply 10.0 V with a 2 A limit, Hall installed, scope on the ESC signal line (D8) and one motor phase, `tools/capture-box.py --silent` running in a second terminal, the main UI as the controlling client, Julian's hand on the supply switch as well as the space bar.
- **Rig T:** the box free on the makeshift turntable, guard ring fitted, same instruments. Used only for the free-box ramp-down.
- **Preflight, every session:** in READY, `tlm.flags` carries none of R4.6's `FF_TABLE_MISSING` (so the T-5 table is loaded), `RATE_GAIN_REDUCED` (so `rate_gain_scale` is 1) and `PARAMS_RESET` (so the box is not running reset defaults); `wheel_ref_rpm` is above 0 as a cross-check; battery reads above 9.6 V.

Interlocks not run in H1 to H11, and why: OVERSPEED (R3.8's test-cap trip, which needs the bench-only override, is cited, not repeated); CONTROL_STALL (R3.4's bench-build stall test, reset in under 150 ms, is cited, because the stall hook is not in the flight build); MOMENTUM_NEAR_LIMIT (a flag only, host-tested in `test_modes.cpp`). Each citation must name the commit it was run on.

**T-12 record.** The wheel is the only thing that can hurt anyone, so the record is: time from the last DShot edge on the scope to the first 5 % drop in wheel_rpm (expected 0.3 s, TD §5.2); time to fall under 800 rpm and to 100 rpm; which event the box posted (expected UNDERSPEED); and the same decay for H10. If the ESC keeps driving more than 1 s after the signal stops, the TD's own fallback applies: rely on the firmware watchdog alone, and A-17, TD §10.1 "Runaway wheel" and §5.2 are rewritten. Either way the numbers go in TD §12.2.

**T-15 protocol (PR-1, ten trials).** Bench console on the real box, Rig T, `rate_gain_scale` 1 sent, guard ring on, Julian's go before each motor-capable block.
1. Arm, READY, `mode DETUMBLE` from rest.
2. The operator spins the box by hand against the loop and lets go. `capture-box.py --silent` records `tlm` throughout.
3. A trial is valid when the peak |rate_dps| after release is 270 to 450 deg/s (0.75 to 1.25 rev/s), MOMENTUM_SATURATED was not set, and the mode stayed DETUMBLE for 10 s after the peak. Invalid trials are discarded and repeated; a discarded trial is still listed in the Notes.
4. t0 is the frame with the peak |rate_dps|. A trial passes when |rate_dps| is under 5 deg/s from t0 + 5.0 s through t0 + 10 s.
5. Ladder first: two uncounted trials at about 0.25 and 0.5 rev/s. Then ten counted trials, five clockwise and five counter-clockwise (the wheel's limits are not symmetric).
6. All ten pass. One failure fails the run; the cause is fixed and all ten are repeated. Nothing is dropped from the record.

`tools/check-trials.py detumble capture.jsonl` applies steps 3 and 4 and prints a row per trial (peak, t_settle, flags). It exits 1 on fewer than 10 valid trials or any failed trial.
