# R4.2: Gyro-integrated heading

**Status:** in progress
**Files:** `firmware/components/direcsun_core/{include/direcsun/core/estimator.hpp,src/estimator.cpp}`, `firmware/components/direcsun_core/src/modes.cpp` (`zero_heading` handling), `firmware/test/host/test_heading.cpp`, `docs/firmware-design.md` (§11.3, §23 row), `docs/technical-design.md` (§6.4, §12.4 row)

## Spec

**Problem:** The UI's judge sequence turns the box 90°, holds 1 s, and returns, so the firmware needs a heading estimate. The FD heading (§11.3) fuses a calibrated magnetometer, but that calibration (T-9 at three wheel speeds) belongs to Set 5. The sequence lasts 5 to 6 s. The gyro bias is estimated while still (R3.4), so its residual should leave a drift well under PR-2's ±3° settle band over that time. That claim is measured here, not assumed.

**Approach:**
- **Integration.** ψ̂ += ω̂ · Δt every control tick, in the internal counter-clockwise frame. ψ̂ is kept continuous as `double` (FD §11.3, storage row) and wrapped only for `psi_deg`; the UI unwraps it.
- **`zero_heading`** (already in schema v1) is accepted in SAFE and READY and stores an offset so ψ̂ reads 0 at the current orientation. A judge sequence starts from a zeroed heading (R4.1 decides who sends it).
- **Heading validity.** A `HEADING_GYRO` flag in `tlm` says the heading is gyro-only; Set 5 replaces it with magnetometer fusion. This is an additive v1 change, with a fixture and a `protocol/README` Changes entry. The flag exists so no UI or operator mistakes the heading for absolute.
- **Guard amendment (approved by Julian 2026-10-10).** FD §13.1 refuses HOLD and SLEW without a magnetometer. With gyro heading, HOLD and SLEW are allowed for relative use: SLEW targets are interpreted relative to the last `zero_heading`. FD §13.1 and TD §6.6 gain the rule, with log rows. Absolute HOLD against a compass reference stays Set 5 (R5.1).

## Tests
- [ ] Host: integration of a sampled gyro trace (constant 30 deg/s for 3 s) gives 90° ± 0.1°. Wrapping at ±180 is correct while the continuous value keeps growing. `zero_heading` reads 0 immediately and is refused outside SAFE/READY. Positive control: integrating with the bias-corrected rate replaced by the raw rate makes the 0.5 deg/s-bias trace test fail.
- [ ] Schema: the `HEADING_GYRO` flag fixture validates; `check-schema`, `check-protocol`, and `check-link` pass.
- [ ] Hardware drift, no motion beyond holding still. In READY with the wheel at bias, held still by the rate loop (R3.9) on the turntable, the heading drifts under 1° in 10 s, logged from `psi_deg`. Independent check: a protractor mark on the turntable shows no visible rotation. Needs Julian's go to arm.
- [ ] Hardware accuracy: turning the rig by hand 90° clockwise to a protractor mark (the box in SAFE, wheel stopped) reads +90 ± 3° in the UI (clockwise positive on the wire). Turning it back reads 0 ± 3°.
