# Workstreams

Two people, each with their own agent sessions, work in this repository. This file is the split between them and the rules for crossing it. Every agent reads it at the start of a session (AGENTS.md, step 1). It replaces the ownership in TD §11.5 as of 2026-10-10.

## Who owns what

| Path | Owner | Notes |
| --- | --- | --- |
| `frontend/` | **Aaron** | The main UI. Only Aaron's work edits it |
| `firmware/` | **Julian** and **Aaron** | Drivers, control task, supervisor, loops, comms (Wi-Fi, WebSocket, protocol encode and decode) |
| `protocol/` | **Julian** | The wire contract. Aaron requests changes (see below) |
| `tools/mock-box.py`, `tools/capture-box.py` | **Julian** | The stub box the UI is developed against |
| `ground/link/`, `ground/console/` | **Julian** | Engineering bench tools, never shown to judges |
| `cad/`, `cad/out/`, `frontend/public/assets/direcsun.glb` | **Julian** | CAD, printing, and the GLB the UI loads (generated by `tools/build-cad.sh`) |
| `docs/` | **Julian** | Design documents |
| `changes/` | **Julian** | Spec-driven sets; Aaron's requests arrive as issues, not edits |
| `README.md`, `AGENTS.md`, `WORKSTREAMS.md`, `changes/CONTEXT.md`, `.github/` | Shared | Small PRs, either person, reviewed by the other |

## Julian: printing, hardware, low-level firmware, wire contract

- **Printing** (`cad/README.md` has the print plan): plates 1 to 3 now, plate 4 once the motor height is confirmed at 37 mm or less. Set 2's parts follow its measurements.
- **Measurements for Set 2:** magnets (diameter, thickness, count, which face is south); motor top (collar, bell screw holes, thread hand, nut or adapter); motor height; the washer stack test result; perfboard size.
- **Bench electronics, then perfboard:**
  - A1104 Hall to D10, with a 12 kΩ pull-up to 3.3 V;
  - the 100k/22k battery divider to D9, fed from the bench supply until the pack exists;
  - a D2 to D3 jumper for the DShot loopback;
  - the ESC signal to D8, with ESC power straight from the bench supply (fuse, 470 µF cap);
  - the OP550s to D0 and D1;
  - later, the 5 V buck and Schottky path.

  Also a makeshift turntable.
- **Firmware, Sets 3 to 5:** agents build it, and Julian runs every bench check. Only Julian arms or spins the motor (CONTEXT.md safety rules).
- **The wire contract:** `protocol/schema-v1.json`, the mock box, and the link module. Every contract change, including the ones Aaron's UI needs.

## Aaron: frontend and integration

- **Operator client in `frontend/ground-station/`:**
  - arm and disarm, with a lock-pin confirmation;
  - e-stop (button and space bar);
  - a 5 Hz `ping` heartbeat while controlling;
  - acks matched by `seq`;
  - no automatic reconnect.

  Test it against `tools/mock-box.py`.
- **Command design:** decide what the UI sends for the judge sequence (rotate ±90, hold 1 s, return): the UI sequencing SLEW commands itself, or one command to the box. Send that to Julian as a contract request. The backend implements what the UI sends (Set 4, R4.1).
- **Display:** `flags` (HALL_BYPASS, MOMENTUM_*, latched faults), `wheel_ref_rpm`, `throttle_band`, and events (they arrive only after the UI has sent a message).
- **Fixes:** #2 (self-host the fonts, which also fixes the flaky `MOCK_ONLY` test), the landing page's flywheel copy, and the URL field at 375 px.
- **3D model:** set `cubesatModel.available` to `true` in `frontend/shared/data/assets.ts` (the ground station reads it) once Set 2 lands the GLB.
- **Integration testing:**
  - the UI against the mock box now;
  - against the real box once R3.5 runs on hardware, with Julian at the bench: "main UI reads the real box" and T-11 telemetry rate and latency.
- **Pitch and demo script.**

## Crossing the line

- **Aaron needs something from the box or the contract** (a new command, field, or mock behaviour): open a GitHub issue titled `Contract: <what>`, with the `contract` label, assigned to Julian. Describe what the UI will send and expect. Julian's agent specs it in `changes/`, then changes the schema, the firmware, and the mock box together, and adds an entry to `protocol/README.md` "Changes". Until it lands, the UI can code against the request; nothing in `protocol/` is edited from Aaron's side.
- **Julian changes the contract:**
  - Additive v1 changes are listed in `protocol/README.md` "Changes" and in the PR description.
  - A breaking change bumps `v` and needs Aaron's ack on the PR before merge.
- **Never edit the other person's paths.** If an agent finds a defect there, it opens an issue assigned to the owner (as with #2).
- **Branches and merges:**
  - Julian: `feat/setN-slug` and `feat/setN/RN.M-slug`.
  - Aaron: `feat/ui-<topic>` off `main` (stacked PRs are fine, as with #10 on #9).
  - Everything reaches `main` by PR with CI green (checks, firmware, frontend).
- **Where status lives:**
  - open sets in `changes/*/_set.md`;
  - Aaron's checklist in #6;
  - contract requests as `contract` issues.
